# CLAUDE.md

Guidance for AI assistants (Claude Code and others) working in this repository.

## What this is

A static website repo deployed via **GitHub Pages** — no build step, no
package.json, no framework. It's plain HTML/CSS files served directly from the
repo root. There is no local dev server; "developing" here means hand-editing
HTML/CSS files and pushing to `main` to trigger a Pages deploy.

The repo currently serves the **`privacy.zerosonesstudio.com`** custom domain
(see `CNAME`). The root `index.html` is a meta-refresh redirect to `/privacy/`,
which hosts the actual Privacy Policy page for "Zeros & Ones Studio" and its
mobile app **Pipeline Pulse**. The `ai-operator-skill-pack/` directory is a
separate static landing page for a digital product ("AI Operator Skill Pack",
sold via Gumroad) that happens to live in the same repo/domain at
`/ai-operator-skill-pack/`.

> Note: `README.md` describes this as the main `zerosonesstudio.com` site with
> a link to `/privacy`, but the live `CNAME` currently points the deployed site
> at `privacy.zerosonesstudio.com`. Don't be surprised by this mismatch — check
> `CNAME` and `git log -- CNAME` if domain routing matters for your task.

## Key conventions

- **Hand-written pages (`index.html` at root, `privacy/index.html`)**: plain
  HTML with an inline `<style>` block using CSS custom properties (`--ink`,
  `--blue`, `--gray-mid`, etc.) modeled on an Apple-style design system
  (San Francisco / Inter fonts, 12px/980px pill buttons, `--radius-md: 12px`).
  Keep edits to these files in the same hand-written style — don't introduce a
  build tool just to tweak copy or styling.
- **`ai-operator-skill-pack/index.html`**: this is **generated output from an
  Astro build** (see commit `6d3772b`: "Built from
  `/Users/data/.hermes/workspace/ai-operator-lp/dist/`, fixed CSS paths for
  subdirectory deployment"). It is minified/single-line and references hashed
  asset filenames in `_astro/`. Treat this directory as a build artifact:
  - Do **not** hand-edit the minified HTML or CSS unless making a small,
    surgical fix (e.g., a typo or a link URL) — the source lives in a
    different (external) Astro project, not in this repo.
  - If assets are regenerated from the Astro source elsewhere, they must be
    copied in with paths rewritten for subdirectory deployment
    (`../_astro/...` relative paths), exactly as the existing build was.
  - Asset filenames include content hashes (e.g., `index.DxdDuXQd.css`,
    `client.BpEju3qh.js`) — if you replace them, update every reference.
- **CNAME files**: GitHub Pages requires the `CNAME` file at the repo root to
  set the custom domain for the whole site; `privacy/CNAME` is a duplicate
  left over from when `/privacy/` may have been deployed independently. Be
  careful changing either — it directly affects DNS/domain routing for the
  live site. Treat CNAME edits as high-impact/external-facing changes.
- **No JS frameworks, no bundlers, no tests** for the hand-written pages. Don't
  add a build pipeline, package.json, or dependencies unless explicitly asked.
- Contact email used across pages: `hello@zerosonesstudio.com`.

## Development workflow

1. There is no install/build/test step — edit the HTML/CSS files directly.
2. Preview by opening the HTML file in a browser, or run a trivial static
   server (e.g. `python3 -m http.server`) from the repo root if you need
   relative paths/redirects to resolve correctly.
3. Commit and push to `main` (or the working branch) — GitHub Pages rebuilds
   and deploys automatically on push. There is no CI/`.github/workflows`
   configuration in this repo.
4. Because this is a live, public-facing site tied to a real product (Pipeline
   Pulse) and a paid digital product (AI Operator Skill Pack), treat content
   changes — especially to the Privacy Policy, contact info, pricing, and
   external links (Gumroad URLs) — as user-facing and double-check before
   pushing.

## Things to watch out for

- **Don't break the redirect chain**: root `/index.html` → `/privacy/`. If you
  restructure pages, make sure the meta-refresh `content="0; url=/privacy/"`
  and `<link rel="canonical">` stay correct.
- **External links**: pages link out to `https://zerosonesstudio.com`,
  `https://zerosonesstudio.gumroad.com`, and a specific Gumroad product URL
  (`/l/lmyxik`) for the Skill Pack. Verify these are intentional before
  changing — they're revenue-relevant links, not arbitrary references.
- **Self-hosted fonts**: the Skill Pack page self-hosts Geist Sans/Mono font
  files (`.woff`/`.woff2`) under `_astro/` rather than loading from a CDN —
  preserve this if regenerating assets.
